# Список расхождений: ТЗ vs Реализация «Зайка ОС 1.0»

Документ фиксирует текущие отклонения от первоначального технического задания для последующего планомерного устранения.
Последнее обновление: 2026-09-19

## БЛОК A: Проблемы, зафиксированные ранее

### A-1. Неправильные категории в ТВ-лаунчере
* **По ТЗ:** 6 фиксированных плиток: 🎬 Фильмы (HDrezka), ▶ YouTube (SmartTube), 🎮 Игры, 🌐 Браузер (Chrome), ⚙ Настройки, 🖥 Рабочий стол.
* **Факт:** Лаунчер LtvLauncher показывает стандартные категории «TV Apps • 4», «Non-TV Apps • 14», «Favorites • 0».
* **Причина:** База данных SQLite лаунчера (`/data/data/com.leanbitlab.ltvL/app_flutter/db.sqlite`) не преднастроена — используются дефолтные категории.
* **Статус:** 🔴 Не исправлено

---

### A-2. AmneziaVPN не отображается в лаунчере
* **По ТЗ:** VPN должен быть доступен прямо с главного экрана.
* **Факт:** AmneziaVPN отсутствует в системе совсем — не установлен.
* **Причина 1:** APK (`AmneziaVPN.apk`) в составе ISO имеет ABI `x86_64`, а процессор неттопа AMD E-450 работает в режиме `x86` (32-bit Android). Несовместимость ABI → установка невозможна.
* **Причина 2:** Скрипт `zaika_setup.sh` не выполнял установку через `pm install` — использовалась только pre-populate в `/data/app`, что не работает для приложений с нативными библиотеками.
* **Нужно:** Заменить на `AmneziaVPN_android7_x86.apk` (4.8.11.0, x86, Android 7+). Файл скачан локально.
* **Статус:** 🔴 Не исправлено

---

### A-3. Нетоп зависает на синем экране после установки
* **По ТЗ:** Система должна загружаться до рабочего лаунчера за 5–10 секунд после установки.
* **Факт:** После успешной авто-установки на `/dev/sda` нетоп загружает ядро, показывает синий экран и зависает. Нет анимации зайки, нет лаунчера.
* **Возможные причины:**
  1. **Видеодрайвер Radeon:** AMD E-450 использует встроенный GPU Radeon HD 6320. Параметр `radeon.modeset=1` передаётся в ядро, но может не подойти для этого GPU (нужно `nomodeset` или `radeon.modeset=0`).
  2. **Параметр `quiet`:** Скрывает все ошибки загрузки — невозможно видеть что именно зависает.
  3. **Нет `vga=` параметра:** PrimeOS/Android-x86 может не перейти в нужное видеорежим без явного указания `vga=788` или `video=LVDS-1:1920x1080`.
* **Обходное решение для диагностики:** Убрать `quiet`, заменить `radeon.modeset=1` на `nomodeset`.
* **Статус:** 🔴 Критическая проблема, не исправлено

### A-4. Оконный режим DecoView (рамка окна с «_ [ ] X»)
* **По ТЗ:** Полноэкранный ТВ-интерфейс без рамок.
* **Факт:** LtvLauncher запускается в плавающем окне с серой шапкой.
* **Причина:** PrimeOS оборачивает приложения из `/data/app` в Freeform/DecoView.
* **Статус:** 🟡 Частично — на VM исправлено через разворачивание окна, на неттопе не проверено

---

### A-5. Экран «Запуск Android...» вместо «Зайка ОС»
* **По ТЗ:** Брендинг «Зайка ОС» везде, никаких упоминаний Android.
* **Факт:** При первой загрузке или сбросе настроек появляется экран AOSP FallbackHome с надписью «Запуск Android...».
* **Статус:** 🟡 Частично исправлено (prime_prefs.xml + настройки), но не гарантировано на неттопе

---

### A-6. ISO-образ не загружен в GitHub Releases
* **По ТЗ:** Репозиторий должен содержать актуальный ISO для скачивания и OTA-обновлений.
* **Факт:** В репозитории `dorokhin95/zaika-os` есть теги `v1.0.0`, `v1.0.1`, но ни один не содержит прикреплённый ISO-файл в Releases (GitHub Assets пусты). OTA-скрипт (`zaika-ota.sh`) не может работать без реального артефакта.
* **Статус:** 🔴 Не исправлено

## БЛОК B: Новые проблемы, выявленные при тестировании на неттопе (2026-09-19)

### B-1. ~~Синий экран / зависание при загрузке с диска на неттопе~~ ✅ РЕШЕНО
* **Симптом:** После установки неттоп зависал на синем экране, KMS-инициализация Radeon вешала видеовыход.
* **Причина:** Современные ядра (5.x/6.x) конфликтуют с архитектурой GPU TeraScale 2 (Radeon HD 6320 в AMD E-450).
* **Решение:**
  1. Переход на **PrimeOS Classic (Android 7.1, ядро 4.14/4.19)** — старый графический стек Mesa нативно поддерживает HD 6000.
  2. Правильные параметры ядра в GRUB: `radeon.modeset=1 vga=current AUTO_LOAD=old_mod`
     - `radeon.modeset=1` — нативный открытый Radeon-драйвер с аппаратным ускорением
     - `vga=current` — запрет сброса видеорежима, установленного BIOS/GRUB
     - `AUTO_LOAD=old_mod` — загрузка старых проверенных модулей для GPU предыдущих поколений
* **Статус:** ✅ Решено пользователем

---

### B-2. Неправильный ABI для AmneziaVPN (x86_64 вместо x86)
* **Симптом:** AmneziaVPN не устанавливается на неттоп с AMD E-450.
* **Причина:** Android на AMD E-450 работает как `x86` (32-bit userspace), а в ISO лежит `AmneziaVPN.apk` с ABI `x86_64` только.
* **Решение:** Заменить на `AmneziaVPN_4.8.11.0_android_7_x86.apk`.
* **Статус:** 🔴 Новая проблема

---

### B-3. Категории LtvLauncher не соответствуют ТЗ
* **Симптом:** На неттопе отображается «TV Apps • 4», «Non-TV Apps • 14» вместо 6 плиток по ТЗ.
* **Причина:** Скрипт не преднастраивает БД `db.sqlite` лаунчера. Структура БД известна (таблицы `categories`, `apps_categories`, `apps`). Нужно залить готовую преднастроенную БД при установке.
* **Статус:** 🔴 Новая проблема

---

### B-4. Сеть внутри VM не позволяет передавать файлы с хоста
* **Симптом:** `wget http://10.0.2.2` из VM возвращает «Network is unreachable» несмотря на наличие маршрута.
* **Причина:** Android-x86 использует policy routing с fwmark — стандартный маршрут по умолчанию игнорируется без явного правила `ip rule add from all lookup main pref 1`.
* **Влияние:** Задерживает доставку APK в VM для тестирования. На реальном железе этой проблемы нет.
* **Статус:** 🟡 Обходное решение найдено
